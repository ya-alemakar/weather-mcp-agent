# AI-помощник по погоде через удалённый MCP

Локальный чат на русском: **пользователь → LLM-агент eve → https://weather.chukai.io/mcp → Open-Meteo → ответ**.
Собственный MCP-сервер не создаётся и не запускается. Локальные HTTP-порты обслуживают только приложение и runtime агента.

## Запуск

Требуется Node.js 24+ и интернет.

```powershell
npm install
Copy-Item .env.example .env  # только если .env ещё не существует
```

В `.env` вставьте ваш ключ **OpenAI API**:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-6.1-sol
```

Вместо него можно использовать `AI_GATEWAY_API_KEY` от Vercel. Это разные ключи: ключ OpenAI нельзя вставлять в поле AI Gateway. При наличии обоих используется OpenAI напрямую. Ключи остаются на сервере, `.env` исключён из Git. Погодный сервер ключа не требует. API модели оплачивается отдельно от погодного сервиса.

```powershell
npm start
```

Откройте http://127.0.0.1:3000. Для остановки — Ctrl+C. После изменения `.env` перезапустите приложение. Порт 2000 используется runtime eve, порт 3000 — чатом. Приложение слушает только localhost.

## Демонстрация

1. Отправьте «Какая сейчас погода в Екатеринбурге?».
2. В том же чате отправьте «А в Казани?».
3. Справа проверьте журнал: `weather__geocode_location`, затем `weather__get_weather_forecast`, город, параметры и статус результата. Раскройте «Параметры и ответ» для сырых данных MCP.

Модель сама ищет инструменты через `eve__search` и вызывает их через `eve__tool`. Координаты получает от MCP, ветер запрашивает в м/с. История хранится в сессии eve. Браузер передаёт идентификатор той же сессии во втором запросе. «Новый чат» начинает отдельный разговор.

## Проверки

```powershell
npm run check       # TypeScript
npm test            # защита от ответа без данных и отказ соединения
npm run check:mcp   # настоящий удалённый MCP без LLM и без ключа модели
npm run check:agent # оба вопроса через запущенный чат, настоящую LLM и MCP
```

`check:mcp` сохраняет `artifacts/mcp-check.json` с инструментами, аргументами и ответами сервера. Это проверка интеграции MCP, а не доказательство выбора инструментов LLM.
`check:agent` проверяет оба вопроса в одной сессии, новый вызов погоды на каждом ходе и сохраняет `artifacts/agent-check.json`. Для неё нужен работающий `npm start` и действительный ключ модели с доступом к выбранной модели.

## Ошибки

При пустом ключе интерфейс сообщает о необходимости настройки. При отказе модели, ошибке MCP или отсутствии погодных данных приложение сообщает об ошибке. Ответ модели с погодой отображается только после успешного вызова MCP-инструмента прогноза в текущем ходе и проверки наличия погодных данных; данные из предыдущего города не заменяют новый запрос.

Чтобы проверить отказ удалённого подключения целиком: временно установите в `.env` `WEATHER_MCP_URL=http://127.0.0.1:1/mcp`, перезапустите приложение и задайте вопрос. Ожидается сообщение о невозможности получить погоду без значений температуры. Верните `https://weather.chukai.io/mcp` и снова перезапустите. Никакой тестовый MCP-сервер для этого не нужен.

При такой конфигурации `npm run check:error` автоматически проверяет сообщение об ошибке и сохраняет `artifacts/error-check.json`. Эта проверка намеренно ожидает отказ и не предназначена для обычного рабочего подключения.

Основные файлы: `agent/instructions.md` — поведение модели; `agent/tools/weather__*.ts` — доступные модели MCP-инструменты; `agent/lib/remote.ts` — клиент официального MCP SDK, вызывающий tools/call удалённого сервера; `server.mjs` — чат и журнал вызовов; `lib/trace.mjs` — проверка данных перед показом ответа.
